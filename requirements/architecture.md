# Архитектура приложения

# **Версия 0.6**

**Статус:** спецификация первой версии (v1)

## 1. Назначение и границы проекта

Advent Tag Studio — бесплатный браузерный редактор для создания печатных бирок для адвент-календаря.

В перспективе продукт может включать редакторы наклеек и поздравительных открыток, однако первая версия поддерживает только Advent Tags.

Приложение работает без собственного backend: создание проекта, редактирование, проверка макета, сохранение состояния и экспорт PDF выполняются на стороне клиента.

## 2. Технологический стек

- React и TypeScript.
- Vite для сборки и разработки.
- SVG для отображения карточек и их редактируемых элементов.
- Клиентская генерация PDF.
- GitHub Pages для статического хостинга.
- `localStorage` для автосохранения проекта и общих недавних цветов.

Конкретную библиотеку PDF следует выбирать с учётом точности геометрии, поддержки встраивания шрифтов и корректного вывода SVG. Необходимо предусмотреть проверку лицензий шрифтов.

## 3. Структура приложения

Основные логические модули:

1. **Template Gallery** — галерея шаблонов и увеличенное превью.
2. **Project Creation** — выбор количества карточек и создание проекта.
3. **Editor** — рабочая область, выбор карточки и редактирование элементов.
4. **Element Libraries** — встроенные иллюстрации, шрифты, цвета и фоновые пресеты.
5. **Bulk Operations** — массовое применение свойств к текущей карточке или всему набору.
6. **History** — Undo/Redo.
7. **Validation** — проверка карточек и печатной раскладки.
8. **PDF Preview and Export** — постраничный предпросмотр, проверка и генерация PDF.
9. **Persistence and Recovery** — автосохранение, восстановление и обработка повреждённых данных.
10. **Help and Instructions** — справка, интерактивный тур и формирование технического отчёта.

Модули взаимодействуют через общее состояние проекта и явно определённые операции изменения состояния. Компоненты интерфейса не должны самостоятельно изменять сохранённые данные в обход этого механизма.

## 4. Модель проекта

Проект содержит:

- идентификатор и версию схемы данных;
- выбранный шаблон;
- фиксированное количество карточек: 24 или 31;
- упорядоченный список карточек;
- состояние каждой карточки;
- настройки элементов;
- данные, необходимые для проверки и экспорта.

Карточки имеют постоянные служебные номера от 1 до выбранного количества. Порядок карточек фиксирован: перестановка и дублирование в v1 не поддерживаются.

Каждая карточка содержит ровно один текстовый элемент, одну основную иллюстрацию и один фон. Дополнительно допускается от 0 до 10 декоративных элементов. Обязательные элементы нельзя удалить.

Шаблон задаёт начальную форму карточки и исходное оформление. После создания проекта заменить шаблон целиком нельзя: для другого шаблона требуется создать новый проект.

Размеры хранятся в физических единицах, пригодных для точного вывода в PDF. Интерфейс показывает размеры карточек и декораций в сантиметрах, размеры текста — в пунктах.

## 5. Галерея и создание проекта

Все шаблоны доступны для наборов из 24 и 31 карточки. Фильтров в галерее v1 нет. Для каждого шаблона показываются превью, название и короткое описание.

При клике на шаблон открывается увеличенное превью. Оно содержит три примера карточек одного шаблона: первая показана крупно, две другие доступны пролистыванием влево. Пользователь может закрыть превью крестиком, клавишей Esc или кликом по оверлею.

Внутри превью находится кнопка «Выбрать шаблон». После её нажатия в том же окне отображаются два варианта количества — 24 и 31 карточка. Выбранный вариант отмечается рамкой и галочкой. Отдельное окно для выбора количества не создаётся.

После выбора количества появляется кнопка «Создать проект». Только после её нажатия начинается создание. На время операции показывается короткая анимация с текстом «Создаём проект…», без искусственной задержки при мгновенном выполнении.

После создания пользователь попадает в редактор: первая карточка выбрана, в центре показана крупно, а остальные доступны в нижней полосе миниатюр.

## 6. Редактор и состояние интерфейса

На широком экране используется трёхколоночная структура:

- слева — инструменты и содержимое: текст, изображения, фон;
- в центре — рабочая область с одной выбранной карточкой;
- справа — свойства выбранного элемента или карточки;
- снизу — горизонтальная полоса миниатюр;
- сверху — название приложения, состояние сохранения, Undo/Redo, справка, помощь, предпросмотр и экспорт.

Правая панель контекстная: показывает свойства текста, изображения, декорации или карточки в зависимости от выбора. Клик по пустой области карточки снимает выделение элемента и открывает свойства карточки.

При первом открытии и каждом переключении карточки масштаб автоматически подбирается так, чтобы вся карточка помещалась в рабочую область. Пользователь может приблизить или отдалить её кнопками «+» и «−». Постоянные сетки и линейки отсутствуют; при перемещении и изменении размеров используются направляющие и мягкое прилипание.

На планшетах панели адаптируются к доступному пространству. На мобильных устройствах рабочая область остаётся главным элементом, а настройки открываются в компактных панелях или выдвижных слоях.

## 7. Миниатюры и навигация

Нижняя полоса показывает все карточки набора. Каждая миниатюра:

- занимает ячейку одинакового размера;
- сохраняет пропорции карточки и полностью помещает её внутрь ячейки;
- постоянно показывает служебный номер;
- отображает актуальное состояние дизайна;
- для выбранной карточки использует акцентную рамку и лёгкое изменение фона.

Полоса поддерживает горизонтальную прокрутку и кнопки-стрелки по краям. При переключении карточки полоса прокручивается так, чтобы выбранная миниатюра оказывалась примерно по центру, если это возможно.

В заголовке рабочей области показывается номер выбранной карточки, например «Карточка 7 из 24». Переключение карточки не требует подтверждения. Активная вкладка левой панели и её позиция прокрутки сохраняются.

Отдельные статусы «отредактирована» и «проверена» не используются. Перед экспортом приложение проверяет весь набор автоматически.

## 8. Редактирование и массовые операции

Каждая операция изменения состояния проходит через общий механизм команд. Он обеспечивает обновление интерфейса, валидацию затронутых карточек, историю действий и автосохранение.

Поддерживаются редактирование текста, изменение шрифта и оформления, замена и перемещение иллюстраций, изменение фона и формы карточки, добавление и настройка декораций.

Массовое применение доступно в двух режимах: «Текущая карточка» и «Весь набор». После выполнения массовой операции режим возвращается к «Текущая карточка». Текстовое содержимое и индивидуальное положение текстовых блоков массовыми настройками не перезаписываются.

Для массовых операций истории создаётся один шаг на всю операцию. Undo/Redo работают в обратном порядке, новая операция после Undo удаляет ветку Redo. Хранится до 15 шагов. История сбрасывается после обновления страницы, хотя состояние проекта восстанавливается.

## 9. Сохранение и восстановление

Существует один активный проект в `localStorage`. Автосохранение запускается через 300–500 мс после последнего изменения. При уходе со страницы предпринимается повторная попытка сохранения; также используется стандартное предупреждение браузера о возможной потере несохранённых изменений.

При первом запуске показывается предупреждение, что проект сохраняется только в текущем браузере и может быть потерян при очистке данных браузера. Оно показывается один раз.

При успешном восстановлении проекта история действий начинается заново. При несовместимых или повреждённых данных приложение пытается восстановить проект, предварительно сохранив локальную резервную копию. Если восстановление не удаётся, пользователь может повторить попытку, скачать повреждённые данные или начать новый проект после удаления повреждённых данных.

Если сохранение не удалось, редактор продолжает работу, где это возможно, и показывает предупреждение с рекомендацией скачать PDF. После успешного сохранения предупреждение скрывается.

Перенос проекта между браузерами и устройствами, облачная синхронизация, экспорт и импорт редактируемого проекта в v1 не поддерживаются. PDF не является редактируемой резервной копией.

## 10. Проверка и экспорт PDF

Экспорт состоит из отдельных этапов:

1. пересчёт раскладки;
2. проверка размеров карточек и содержимого;
3. проверка доступности шрифтов и возможной подстановки;
4. предпросмотр страниц A4;
5. генерация PDF.

При каждом открытии предпросмотра и возвращении из редактора выполняется повторный пересчёт и проверка. Экспорт блокируется при наличии ошибок, включая выход текста за границы блока и выход карточек или содержимого за печатную область A4. Предупреждения и рекомендации сами по себе экспорт не блокируют.

В v1 используются автоматически рассчитываемые поля и промежутки, без масштабирования карточек. Минимальный промежуток между карточками — 3 мм. Регулярные страницы должны содержать не менее четырёх карточек, последняя страница может содержать меньше; максимум — 20 карточек на страницу. Если размеры делают раскладку невозможной, пользователь получает предупреждение.

PDF содержит тонкую светло-серую пунктирную линию по точному периметру карточки для вырезания. Имя файла — `Advent-Tags.pdf`, заголовок метаданных — `Advent Tags`. Автоматическое уменьшение текста или карточек не допускается.

Если шрифт нельзя встроить, используется ближайшая доступная замена и показывается предупреждение. Проверка переполнения текста проводится с учётом замены; если текст не помещается, экспорт блокируется до ручного исправления.

## 11. Справка и обучение

«Справка» открывает инструкцию и FAQ. После создания первого проекта пользователю предлагается пройти интерактивный тур по редактору. Тур запускается только по желанию; его можно пропустить. При повторном запуске пользователь проходит весь тур с самого начала. Отдельные туры по темам в v1 не предусмотрены.

«Помощь» открывает отдельное окно для описания проблемы, копирования технического отчёта и перехода к GitHub Issues. Отправка обращения автоматически не выполняется. Технический отчёт не включает тексты карточек и их содержимое.

## 12. Ограничения первой версии

Не входят в v1: редакторы наклеек и открыток, загрузка собственных изображений, поиск изображений в интернете, ручная перестановка и дублирование карточек, произвольные группы для массовых операций, перенос и синхронизация проектов, редактируемые резервные копии, ручные параметры печати, экспорт PNG/JPEG, экранные дикторы и дополнительные функции доступности для них.

Все изменения должны сохранять локальную работу приложения без backend и обеспечивать предсказуемый вывод карточек на печать.
