# Технические решения реализации

## T00 — основание

- React, TypeScript в strict mode, Vite; локальная разработка и статический артефакт для GitHub Pages. Публикация и push не выполняются.
- Физическая геометрия в миллиметрах, текст и обводка в пунктах. Начальный шаблон — 50 × 80 мм. Zoom не меняет документ.
- A4 portrait, печатные поля 10 мм, минимальный промежуток 3 мм; автоматическая раскладка без масштабирования.
- Защитный лимит текста 6000 символов (по визуальному образцу): ограничивает объём ввода, физическое переполнение проверяется независимо.
- Кандидаты локальных шрифтов: PT Sans, PT Serif и Bad Script из Google Fonts, с кириллицей и лицензией OFL. Одинаковые TTF используются браузером и PDF.
- Неподдерживаемые начертания не синтезируются; шрифт для PDF разрешается до измерения строк.
- Иллюстрации и фон обрезаются силуэтом карточки; переполнение текстового блока показывается и блокирует экспорт. Выход исходной геометрии изображения за силуэт остаётся предупреждением.
- При смене формы сохраняются допустимые координаты отверстия. Если круг отверстия выходит за новый силуэт, операция не фиксируется: необходимо сначала убрать/переместить отверстие.
- Пользователь 1 ноября уточнил: metadata source of truth — `src/data/images.ts`, все характеристики задаются явно; локальный поиск ru/en и фильтры включены в v1. Оригиналы `assets/` пополняются вручную, подготовка производных не назначает категории.

Источники API/размещения: [Vite — static deploy](https://vite.dev/guide/static-deploy.html), [Google Fonts](https://github.com/google/fonts).

## T01/T09 — вывод на печать

- Выбран нативный jsPDF-адаптер на общей геометрии и рассчитанных строках текста. SVG-маски не передаются стороннему конвертеру: отверстия и clipping выполняются even-odd контурами PDF, шрифты встраиваются как TTF. Неиспользуемая пробная зависимость svg2pdf удалена.
- Экранное A4-превью использует лёгкие изображения, векторный контур и разрешённый фактический шрифт; полноразмерные PNG загружаются только для экспорта.
- Для PDF формируется прозрачная растровая копия до 300 dpi фактического физического размера иллюстрации; исходники не меняются, апскейла нет. Если ресурс повторяется, учитывается его наибольший размер на карточках. Параллельное декодирование ограничено тремя изображениями, кеш оптимизированных ресурсов — 64 записи.
- Раскладка — детерминированное динамическое программирование по разрывам строк и страниц, порядок сохраняется; 10-мм поля, промежуток ≥3 мм, до 20 карточек/страницу и минимум 4 на каждой обычной странице. Последняя может содержать меньше.
- Экспорт и проверка привязаны к неизменяемому snapshot. Устаревшая/закрытая сессия предпросмотра не скачивает файл после завершения асинхронной работы.
- Растровый PDF с 31 уникальной иллюстрацией и 310 декорациями: ~9,58 МиБ и ~3,5 секунды в локальном Chromium, вместо ~66,39 МиБ для полноразмерного варианта. Это измерение на текущей машине, не гарантия для всех устройств.

Источники API: [jsPDF](https://github.com/parallax/jsPDF), [jsPDF API](https://parallax.github.io/jsPDF/docs/jsPDF.html).

## T08 — сохранение

- Одно активное schema-v1 состояние, debounce 400 мс, сравнение фактического raw в хранилище перед перезаписью. Непрочитанные данные и изменения другой вкладки не затираются.
- Последовательный ввод содержимого одного текстового блока объединяется в истории в пределах 800 мс; другая команда, уход фокуса, Undo/Redo и lifecycle-события разрывают группу. Каждая новая revision сохраняется независимо от группировки истории.
- Восстановление повреждений предваряется сохранением исходного raw; произвольная неизвестная схема не угадывается. Безопасные отсутствующие опциональные поля текущей схемы восстанавливаются с резервированием исходника.

## T10 — локальная передача и GitHub Pages

- `pages.yml` публикует только по ручному workflow_dispatch. Checks при push/PR сами сайт не публикуют. В этой сессии ни workflow публикации, ни push не запускались.
- GitHub Pages workflow вычисляет base path и Issues URL из настоящего контекста репозитория. Локально Issues отключены, если `VITE_GITHUB_ISSUES_URL` не настроен; фиктивных адресов в готовой сборке нет.
- Шесть плановых viewport проверены в Chromium. Проверка реального мобильного Safari/Chrome с системной клавиатурой и физическая пробная печать остаются отдельной аппаратной приёмкой.
