# Новогодняя мастерская

«Новогодняя мастерская» — браузерные редакторы печатных адвент-тегов и открыток. React, TypeScript, Vite, SVG и локальный экспорт; собственный сервер и аккаунт не требуются.

## Запуск

Требуется Node.js 22.23 или новее.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. `npm run build` создаёт статический сайт в `dist/`, `npm run preview` запускает просмотр собранной версии.

## Что умеет мастерская

- Главная страница с выбором направления. Работают редакторы адвент-тегов и открыток; стикеры и идеи пока находятся в разработке. Меню «Редактор» и «Шаблоны» предлагают выбор направления.
- Шесть тематических наборов, просмотр трёх примеров, создание 24 или 31 карточки с уникальными случайными иллюстрациями из подборки выбранного набора.
- Узкая навигация слева, инструменты и свойства справа; на телефоне нижние панели.
- Текст на русском и английском, локальные шрифты с кириллицей, цвета и градиенты, пять форм карточек, прозрачное отверстие, круги и звёзды.
- Перемещение, изменение размеров, поворот иллюстрации, направляющие, масштабирование и сенсорные жесты. Двойной клик по тексту открывает ввод на карточке.
- Текущая карточка или весь набор, атомарные массовые операции, Undo/Redo до 15 шагов.
- Сброс оформления к исходному шаблону с подтверждением и возможностью отменить действие; подгонка текстовой рамки под введённый текст без изменения шрифта. Карточка закреплена в рабочей области, перемещаются её элементы. До 25 элементов декора на карточку, Shift сохраняет их текущие пропорции при изменении размеров.
- Автосохранение одного проекта в текущем браузере, восстановление и обработка повреждённых данных.
- Проверка всего набора, предпросмотр страниц A4 и `Advent-Tags.pdf` с настоящими физическими размерами и векторным текстом/контурами.
- Локальный поиск иллюстраций по явно заданным русским/английским метаданным и фильтрам.
- Открытки: 1–20 независимых открыток A6 вертикальных/горизонтальных и квадратных 105 × 105 мм в одном проекте, до 100 элементов на открытку. Несколько текстов, иллюстраций, надписей и фигур, слои, блокировка, дублирование, повороты по 15°, пропорциональное масштабирование графики и отдельный фон каждой открытки.
- Для открыток доступны 207 общих иллюстраций, отдельная подборка по тем же ID, 46 графических надписей, 23 фона и 28 элементов художественного декора. Во вкладке «Текст» выбираются свой текст или готовые надписи; фон и формат объединены во вкладке «Фон и форма». В каталоге есть три чистых стартовых формата и три редактируемые композиции по референсам: вертикальная с Сантой, горизонтальная с эльфом и квадратная с белочками. Иллюстрации и надписи сохраняются отдельными элементами. Обложки шаблонов используют предоставленные фотографии и не входят в печатный дизайн.
- Экспорт открытки в PDF её физического формата, проекта — в A4 с полями 10 мм и зазором 3 мм, без уменьшения дизайна. Текст в PDF остаётся векторными контурами. PNG/JPG имеют размер и метаданные 300 DPI, несколько открыток скачиваются ZIP-архивом.

В `localStorage` этого браузера хранится по одному текущему проекту каждого редактора; их данные и история независимы. Очистка данных удаляет проекты. PDF/PNG/JPG сохраняют готовый результат и не являются редактируемой резервной копией. История действий после перезагрузки начинается заново. Предупреждения допускают экспорт после общего подтверждения, ошибки требуется исправить. Для открыток 3 мм и 300 DPI проверяются при подготовке экспорта; выходы за границы проверяются во время редактирования.

Навигация использует hash-маршруты `#home`, `#tags`, `#editor/tags`, `#postcards`, `#editor/postcards`, `#create`, `#about`, `#stickers`, `#ideas`, `#terms` и `#privacy`, поэтому обновление страницы совместимо со статическим GitHub Pages. Прежние `#editor` и `#templates` открывают редактор и каталог тегов. Общая кнопка создания предлагает направление; на страницах каталогов сохраняется контекст продукта.

В редакторе логотип с ёлками открывает общую главную, пункт «Шаблоны» — каталог текущего направления. На портретных экранах шириной до 1150 px используются нижняя панель инструментов и бургер-меню; на широком десктопе карточки доступны в отдельной нижней ленте. Контекстного меню элементов нет.

Галерея включает «Хвойную сказку», «Зимние истории», «Винтажный праздник», «Лесных друзей», «Тёплые подарки» и «Классическое Рождество». Оформление страниц хранится в `assets/site/`: `hero/` — верхние композиции, `decorations/` — подарок и конверт, `products/` — общие обложки направлений, `templates/` — обложки наборов. Фоны открыток хранятся в `assets/backgrounds/`, готовые декоративные надписи — в `assets/lettering/`. [Структура изображений](./assets/README.md) описывает пополнение; [перечень оформления](./docs/page-image-brief.md) содержит все подключённые иллюстрации. Метаданные оформления находятся в `src/data/site-art.ts`, облегчённые WebP — в `public/site/`. Почта автора и будущая ссылка для отзывов настраиваются в `src/content/siteContacts.ts`.

Публичные страницы используют общий `SiteLayout`: одинаковый хедер, футер в три колонки на десктопе и радиальный градиент. PT Sans и общая шкала H1/H2/H3/основного текста задаются в `src/styles/public-pages.css` для всех публичных страниц и их модальных окон. Редактор сохраняет собственную типографику.

Перед первым созданием проекта показываются условия. Проект создаётся после явной отметки и подтверждения; версия условий и время сохраняются только в этом браузере. При недоступном localStorage принятие действует до закрытия страницы. Публичные юридические тексты находятся в `src/content/legalContent.tsx`, сведения об авторе и версия — в `src/content/legalMetadata.ts`. Политика пока помечена как проект; [проверка фактов и оставшиеся вопросы](./docs/privacy-review.md) описывает её ограничения. Файлы `requirements/` игнорируются Git и не требуются для сборки.

В предпросмотре 100% означает A4 210×297 мм в CSS-единицах при 96 dpi; вписывание показывает фактический меньший процент. Нажатие на значение процента возвращает масштаб 100%, кнопка вписывания подбирает масштаб под доступную область.

## Пополнение изображений

Добавьте PNG в `assets/`, вручную опишите его в [`src/data/images.ts`](./src/data/images.ts), выполните `npm run assets:prepare`. Для каждого исходника нужна отдельная запись с уникальным kebab-case ID, путями `source` и `src`, категорией, подкатегорией, названиями, русскими и английскими тегами, синонимами и типом фона. Подготовленные файлы из `public/art/` и `src/content/image-dimensions.json` включайте в тот же коммит.

Для надписей и фонов есть отдельные справочники [`src/data/lettering.ts`](./src/data/lettering.ts) и [`src/data/backgrounds.ts`](./src/data/backgrounds.ts) с теми же основными полями. У надписи дополнительно указаны текст и язык, у фона — тип композиции. `npm run assets:prepare` обрабатывает иллюстрации, надписи, фоны и декор: надписи и их превью попадают в `public/lettering/`, фоны — в `public/backgrounds/`, декор — в `public/decorations/`. Размеры записываются в соответствующие `src/content/*-dimensions.json`.

Имя исходника должно быть на английском в kebab-case и совпадать с ID: `assets/<id>.png`; печатный путь — `art/<id>.png`. Заглавные буквы, пробелы, кириллица (включая похожую на латинскую «с») и повторные расширения не допускаются. Подготовка проверяет имена, полноту каталога и связи до создания файлов. Существующие ID менять не следует: на них ссылаются сохранённые проекты.

Справочники `categories` и `motifs` содержат восемь основных категорий и мотивы внутри каждой. У изображения одна основная категория и один основной мотив (`subcategory`). Явные `includeTags` в справочниках добавляют связанные направления: например, игрушка с тегами `ornament`, `soviet`, `russian-traditions` находится и в ёлочных украшениях, и в русских новогодних традициях. Изображение хранится одной записью. Цвет, материал и стилистические особенности задаются тегами. В интерфейсе показываются только мотивы с подходящими иллюстрациями; будущий мотив появляется после добавления соответствующей записи.

Категории, подкатегории, теги, синонимы и фон никогда не вычисляются из имени файла. Генератор проверяет связи и уникальность, создаёт WebP-превью и измеряет размеры. Начальная загрузка использует превью; полноразмерные PNG загружаются для PDF. При экспорте растровые изображения подготавливаются к 300 dpi фактического размера с сохранением прозрачности, оригиналы не меняются.

PNG/SVG художественного декора описываются в `src/data/decorations.ts`. Подготовка сравнивает декодированные пиксели и отклоняет точные дубли, включая повторно сохранённые PNG с другими метаданными. Каталоги и старые ID объединённых дублей остаются совместимыми с сохранёнными проектами. Архитектурные контракты открыток описаны в [`docs/postcards-architecture.md`](./docs/postcards-architecture.md).

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

Модульные проверки покрывают инварианты, атомарность, историю, сохранение, recovery, поиск, геометрию, текст и PDF. Playwright проверяет сценарии браузера. Тестовые PDF и скриншоты сохраняются в игнорируемом `artifacts/`; они не попадают в Git.

Соответствие рекомендованным сценариям редактора открыток и изменениям интерфейса описано в [`docs/postcards-test-coverage.md`](./docs/postcards-test-coverage.md).

## GitHub Pages

Workflow [`pages.yml`](./.github/workflows/pages.yml) запускается вручную и публикует `dist/`. В настройках репозитория Pages выберите GitHub Actions. Base path и реальная ссылка Issues вычисляются из имени репозитория. Пока workflow не запущен, публикации нет. Workflow `check.yml` выполняет проверки при push и PR.

Для другого вложенного пути задайте `VITE_BASE_PATH` при сборке. В PowerShell:

```powershell
$env:VITE_BASE_PATH = '/christmas-studio/'
npm run build
```

`VITE_GITHUB_ISSUES_URL` задаёт реальную страницу обращений. В локальной сборке без этой настройки соответствующее действие недоступно; копирование технического отчёта работает. Отчёт не содержит текст и содержимое карточек, обращения автоматически не отправляются.

## Документация

- Локальные требования, макеты и отчёты находятся в `requirements/`. Эта папка исключена из Git; приложение, сборка и тесты от неё не зависят.
- [`docs/page-image-brief.md`](./docs/page-image-brief.md) — изображения для обновлённых страниц галереи и «О проекте».
- Лицензии локальных шрифтов и их источники находятся в `public/fonts/`.
