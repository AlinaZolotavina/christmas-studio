# Как пополнять библиотеку

1. Добавьте PNG-исходник в `assets/`.
2. Откройте изображение и вручную добавьте ровно одну запись в `src/data/images.ts`. Укажите уникальный kebab-case `id`, `source`, `src: 'art/<id>.png'`, название, основную категорию и подкатегорию, русские/английские теги, двуязычные синонимы, фактический фон и при необходимости стиль.
3. При необходимости добавьте категорию/подкатегорию с устойчивым ID и локализованными названиями. Связь подкатегории с родителем обязательна; дополнительные темы задаются тегами, без копий картинки.
4. Выполните `npm run assets:prepare`. Генератор проверит записи/источники, скопирует полноразмерные PNG для печати, создаст лёгкие WebP-превью и обновит только измеренные технические размеры. Пропущенный в метаданных файл приводит к ошибке, категории из имени не вычисляются.
5. Выполните `npm test` и `npm run build`, добавьте исходник, запись, размеры и `public/art/` в коммит.

`src/data/images.ts` — единственный источник тематических метаданных; `src/content/assets.ts` адаптирует его для редактора, `image-dimensions.json` содержит только измеренные размеры. Все runtime-пути разрешаются относительно Vite base path, поэтому работают под GitHub Pages `/имя-репозитория/`.

Поиск учитывает все слова запроса в ID/названиях/категориях/подкатегориях/тегах/синонимах сразу на обоих языках, без привязки к языку интерфейса. Регистронезависим, `ё` и `е` эквивалентны. Фильтры применяются совместно. Для следующего языка добавьте локализованные названия и `tagsByLocale`, поисковую функцию менять не нужно.

Иллюстрации, используемые в мастерской, имеют прозрачное внешнее поле. Кремовые предметы и светлые лепестки внутри иллюстрации не означают фон `ivory`. Поле `background` сохранено в метаданных и поисковом API для совместимости структуры; фильтра по фону в пользовательском интерфейсе нет.
