# Новогодняя мастерская — план реализации для агентов

Дата: 1 ноября 2026 года. Объём: первая версия Advent Tag Studio, редактор печатных адвент-бирок.

Этот документ задаёт порядок реализации, границы ответственности агентов, общие контракты и критерии приёмки. План подготовлен по существующим требованиям и изображениям; перечисленные ниже модули и задачи предстоит реализовать.

## 1. Источники и принятые решения

Обязательные исходные материалы:

- [Архитектура, v0.6](./architecture.md) — стек, модель проекта, сохранение, история и печать.
- [Дизайн и интерфейс, v0.3](./design-and-interface.md) — пользовательские сценарии и ограничения v1.
- [Design System & UI Layout, v0.1 Draft](./design-system-and-UI.md) — токены, геометрия интерфейса, жесты, адаптивность и отверстия.
- [Визуальный образец](./layout-sample.png) — основной ориентир по внешнему виду редактора.
- [Исходные иллюстрации](../assets/) — существующая коллекция PNG.

**Прямое решение пользователя: слева реализуем узкую навигацию, справа — настройки и библиотеки, как в макете.** Оно переопределяет размещение инструментов слева в `architecture.md`, §6, и `design-and-interface.md`, §4. Отдельной широкой левой панели инструментов не будет. Модель данных и остальные функциональные ограничения этих документов сохраняются.

Для остальных расхождений рабочий приоритет: архитектурные инварианты из v0.6 → поведение из v0.3 → визуальная композиция образца → непротиворечивые детали draft v0.1. Это правило реализации данного плана; исходные документы автоматически согласованными не считаются.

| Вопрос | Решение для реализации |
| --- | --- |
| Компоновка desktop | Узкая навигация → рабочая область → правая панель. В правой панели объединены библиотеки содержимого и контекстные свойства. |
| Масштаб при выборе карточки | Автоматически вписывать каждую выбранную карточку целиком. Сохранение масштаба между карточками из draft не применять. |
| Undo/Redo, экспорт, справка | Как в образце: Undo/Redo отдельным островком в рабочей области, основной экспорт внизу правой панели, справка в навигации. Справка и отдельная «Помощь» доступны через навигацию/меню; на телефоне экспорт в нижней панели. Верхняя панель сохраняет состояние проекта и сводку проблем. |
| Статус ошибок | Обязательна сводка всего набора с переходом к проблемной карточке. Статус текущей карточки дополняет её. |
| 12 карточек и «+» в образце | Использовать только 24/31; кнопки добавления, удаления и перестановки карточек не переносить. Количество после создания неизменно, в настройках показывается для сведения. |
| U, выравнивание по ширине, прозрачность в образце | Эти контролы исключить по ограничениям v1. Поддерживать только разрешённые свойства. |
| Название/номер карточки на телефоне | Компактная вторая строка верхней панели по образцу. Не размещать важные сведения за пределами видимого экрана под нижней панелью. |
| Планшет в портретной ориентации | Компоновка с нижними панелями. Доступ к навигации через компактное меню, как в образце; отдельную левую колонку здесь не резервировать. |
| Изменение формы и шаблона | Форма/размеры редактируются; `templateId`, количество и порядок карточек после создания не меняются. |
| Переполнение текста | Блокирующая ошибка, даже если в draft названа предупреждением. Не уменьшать и не обрезать текст автоматически. |
| Выход иллюстрации/декорации | За силуэт карточки — предупреждение; за допустимую печатную область A4 — ошибка. Правила clipping одинаковы в редакторе и PDF. |
| Невозможная раскладка | Объяснить причину сообщением; экспорт недопустимого макета заблокировать. Нельзя обойти ошибку названием «предупреждение». |
| Лимит текста `/6000` | Число в образце не является нормативом. Если нужен защитный лимит, определить общую константу и обоснование в T00; не путать его с проверкой физического переполнения. |
| Отверстие | Включить по draft: максимум одно, действительно прозрачное, автоматически рассчитанного диаметра. |

## 2. Результат первой версии

Полный сценарий: галерея → просмотр трёх примеров шаблона → выбор 24/31 в том же окне → явное создание проекта → редактирование → автосохранение и восстановление → проверка всех карточек → предпросмотр A4 → скачивание `Advent-Tags.pdf`.

Обязательные границы:

- React + TypeScript + Vite; SVG для карточек, миниатюр и экранного представления печати; клиентский PDF; статическая сборка для GitHub Pages.
- Один активный проект в `localStorage`, без собственного backend, регистрации и облачного аккаунта.
- Ровно 24 или 31 карточка с постоянными служебными номерами и фиксированным порядком.
- В каждой карточке один обязательный текстовый блок, одна обязательная основная иллюстрация, один фон и 0–10 декораций.
- При создании — случайные уникальные иллюстрации без повторений внутри набора; назначения сохраняются в проекте, не генерируются заново при рендере.
- История до 15 шагов, одна массовая операция — один шаг; после перезагрузки восстанавливается проект, история начинается заново.
- Размеры карточек и элементов в интерфейсе — сантиметры, шрифт/обводки — пункты; внутри геометрия в миллиметрах.
- Нет загрузки пользовательских картинок, интернет-поиска, перестановки/дублирования карточек, ручного управления слоями, группировки, экспорта PNG/JPEG, импорта/экспорта редактируемого проекта и синхронизации.
- Поддержка клавиатуры, видимого фокуса, системного масштаба текста, browser zoom, повышенной контрастности и Reduce Motion входит в работу. Отдельные функции для экранных дикторов не расширяют объём v1.

## 3. Визуальное направление и адаптивность

### 3.1. Что воспроизводим из layout-sample

Светлая студия с белыми панелями, очень светлым голубовато-серым рабочим полем, лесным зелёным акцентом, кремовой бумажной карточкой и акварельными PNG. Карточка доминирует; границы тонкие, тени мягкие, настройки компактны и разбиты на ясные группы. Рамки устройств и фон презентационного изображения в приложение не переносятся.

В интерфейсе используется современный sans-serif. Serif, sans-serif и handwritten доступны как шрифты самих карточек. Конкретные семейства выбираются после проверки кириллицы и лицензий на локальную поставку и встраивание в PDF; надпись Playfair Display в образце не заменяет эту проверку.

| Токен | Исходная величина |
| --- | --- |
| Главный акцент | `#315C4C` |
| Верхняя панель / левая навигация | 64 px / 64 px |
| Иконка навигации / кнопка | 24 × 24 px / 40 × 40 px |
| Отступы | База 8 px, промежуточный шаг 4 px; внутри панели 16 px; крупные секции 24 px; связанные контролы 8 px |
| Контролы / сенсорная область | Высота 40 px / область нажатия минимум 44 × 44 px |
| Скругления | Поле 4 px, кнопка 6 px, панель 8 px |
| Лента desktop | Высота 128 px, промежуток между миниатюрами 12 px |
| Модальные окна | Ширина 480/640/800 px, максимальная высота 85% viewport; на телефоне ширина экрана минус 32 px |

Остальные HEX, ширина правой панели и границы адаптивных режимов — решения визуального прототипа T02. Не выдавать их за уже заданные требования. Для первой итерации можно проверить правую панель 320–360 px и затем зафиксировать итоговые токены в одном месте.

### 3.2. Структура экранов

- **Desktop:** узкая навигация «Главная», «Настройки», «Справка»; центральная область с одной карточкой; справа вкладки «Текст», «Изображение», «Фон», «Карточки», «Экспорт»; снизу лента миниатюр. «Помощь» доступна отдельным действием внутри раздела справки. Блок масштаба закреплён слева сверху рабочего поля, Undo/Redo — справа сверху, экспорт — снизу правой панели.
- **Правая панель:** верхняя часть отвечает за выбор содержимого, ниже — свойства выбранного элемента. Выбор на карточке открывает соответствующий контекст без потери выбранной карточки. Клик по пустому месту снимает выделение и показывает геометрию карточки/фон. Декорации размещаются отдельной секцией внутри вкладки «Изображение»; второй независимый инспектор не создаётся.
- **Tablet landscape:** компактный desktop; при недостатке места лента переходит во вкладку «Карточки». Не сжимать рабочую область до непригодного размера ради двух одновременно показанных списков карточек.
- **Tablet portrait / phone:** верхняя панель, рабочая область, постоянная нижняя панель `Текст → Изображение → Фон → Карточки → Экспорт`; меню навигации на весь экран. На телефоне в нижней панели только иконки. Имя проекта сокращается первым, индикатор сохранения остаётся видимым.
- **Нижние панели:** одновременно открыта одна; высота настроек не более 75% доступной высоты после вычета header; заголовок и закрытие закреплены, содержимое прокручивается. Закрытие по × или нажатию вне панели; повторное нажатие активной вкладки панель не закрывает. Рабочая область под открытой панелью не принимает редактирование.
- **Карточки на телефоне:** минимум три целые миниатюры и края соседних; текущая центрируется при открытии; выбор другой не закрывает список.
- **Системная клавиатура:** редактируемое поле/текст и закрытие настроек остаются видимыми, после скрытия восстанавливается компоновка. Учитываются динамическая высота viewport и safe area.

Контрольные размеры для приёмки: 1440×900, 1280×800, 1024×768 landscape, 768×1024 portrait, 390×844 и 360×800. Это тестовые размеры, а не заданные спецификацией breakpoints. Выбор режима основан на CSS-ширине, ориентации и доступном месте, без определения устройства по user-agent.

## 4. Архитектура и общие контракты

### 4.1. Предлагаемая структура

```text
src/
  app/                       # запуск, экраны, providers, композиция модулей
  domain/
    project/                 # типы, фабрика проекта, инварианты
    commands/                # типизированные операции и массовые изменения
    geometry/                # мм/pt, формы, границы, трансформации, отверстия
    validation/              # чистые правила ошибок/предупреждений
  application/
    project-store/           # состояние, selectors, dispatch, revisions
    history/                 # транзакции, undo/redo, лимит 15
    persistence/             # autosave, restore/recovery, orchestration
    export/                  # подготовка snapshot, проверка, отмена/повтор
  rendering/
    scene/                   # единое представление карточки для всех выводов
    svg/                     # карточка, миниатюра, печатная страница
    text/                    # переносы, метрики, шрифты, overflow
    interaction/             # selection, pointer/touch, zoom/pan, snapping
  infrastructure/
    storage/                 # localStorage, схема, миграции, raw backup
    assets/                  # загрузка изображений и шрифтов
    pdf/                     # выбранный PDF-адаптер
  content/                   # manifests иллюстраций, шрифтов, шаблонов, пресетов
  features/
    gallery/ creation/ editor/ inspector/
    project-settings/ thumbnails/ print-preview/ help/ onboarding/
  shared/ui/                 # кнопки, поля, modal, sheet, menu, tooltip
  styles/                    # единые tokens и базовые стили
scripts/                     # каталог и производные ассетов
tests/                       # общие fixtures и сквозные сценарии
public/                      # подготовленные статические ресурсы и лицензии
```

Не дробить каждый небольшой компонент на отдельный архитектурный слой. Направление зависимостей: UI → application → domain; внешние загрузчики/storage/PDF подключаются адаптерами. Domain не импортирует React, DOM и `localStorage`. Feature-компоненты вызывают команды и читают selectors.

### 4.2. Состояние и команды

До параллельной реализации координатор фиксирует эти контракты:

| Контракт | Состав и правила |
| --- | --- |
| `ProjectDocument` | `schemaVersion`, стабильный `id`, имя, `templateId`, `cardCount: 24 \| 31`, упорядоченные карточки, настройки проекта. Сериализуемые данные без DOM, функций, base64 и истории. |
| `Card` | Стабильные `id`/служебный номер, форма и размеры, фон, один text, одна illustration по `assetId`, массив decorations, опциональное hole. Порядок слоёв фиксирован. |
| `EditorUiState` | Выбранные карточка/элемент, вкладка, scroll, zoom/pan, режим текста, меню/окна, временная трансформация. Не записывается автоматически в документ и историю. |
| `dispatch(command)` | Проверяет допустимость → меняет документ атомарно → увеличивает revision → обновляет производные данные/валидацию → создаёт шаг истории → планирует сохранение. Undo/Redo также запускают пересчёт и сохранение. |
| `OperationResult` | Изменённые карточки, предупреждения/пропуски, результат операции. Невалидная команда не оставляет частично изменённый проект. |
| `ValidationIssue` | Стабильный code, `error/warning/recommendation`, cardId/elementId/pageIndex при наличии, понятное сообщение и цель перехода «Исправить». |
| `CardScene` | Геометрия, реальные строки текста/метрики, ссылки на изображения, фон, clipping, отверстие; без выделения, ручек, направляющих и других editor overlays. |
| `PrintLayout` | Страницы A4, позиции карточек в мм, поля/промежутки, issues, revision и использованные шрифты. |
| `FontResolution` | Запрошенный и фактический шрифт, начертание, пригодность для PDF и причина замены. Одинаковый результат используется для измерения, предпросмотра и экспорта. |

Дополнительные правила:

- Все координаты и размеры геометрии — мм; см и pt переводятся централизованно (`10 мм = 1 см`, `25,4 мм = 72 pt`). Zoom — только экранное преобразование, не изменение сохранённых размеров.
- Поворот поддерживается только у основной иллюстрации. Фон → декорации → иллюстрация → текст; ручного z-index нет.
- Drag/resize/поворот используют временное состояние и завершаются одной командой. `pointercancel`/Esc отменяет незавершённую трансформацию. Не сохранять каждый `pointermove` отдельным шагом.
- Для текста явно разделить сессию ввода, нативное редактирование и историю документа; сгруппировать набор в осмысленные шаги. Ctrl/⌘+Z внутри поля не должен одновременно отменять операцию проекта.
- Массовые операции имеют явный перечень применяемых свойств. Текстовое содержимое и индивидуальное положение текстовых блоков сохраняются; scope после операции становится «Текущая карточка».
- Производные миниатюры/валидация не хранятся как второй источник истины. Подписки ограничиваются затронутыми карточками; PDF-модуль загружается по необходимости.

### 4.3. Единый путь вывода и печати

Редактор, миниатюры, A4-preview и PDF используют одну геометрию и рассчитанные строки текста. PDF не строится независимым набором координат и не является скриншотом интерфейса. Шрифты загружаются до финальных измерений; PNG остаются растровыми иллюстрациями, формы/контуры/текст выводятся выбранным PDF-адаптером с проверкой точности.

Проверка и экспорт выполняются по одному неизменяемому snapshot/revision. При изменении проекта или разрешения шрифтов результат устаревает: пересчёт обязателен, кнопка скачивания до завершения отключена. Возврат из preview сохраняет выбранную карточку и scroll ленты; повторное открытие всегда пересчитывает макет.

## 5. Подготовка существующих assets

Инвентаризация: в `assets` 54 PNG, суммарно около 129,76 МиБ, размеры от 1086 до 1536 px по ширине и от 1024 до 1448 px по высоте. PNG имеют RGBA-формат; просмотренные ёлка, Снегурочка и венок подходят для единой акварельной коллекции. Количества достаточно для 31 уникального назначения; пригодность и тематические категории проверяются отдельно.

Работа с коллекцией:

1. Оставить исходники в `assets`; сформировать manifest со стабильным ASCII `assetId`, точным путём к оригиналу, локализованным названием, категорией, размерами, путями к preview/print-версии и доступными сведениями об источнике/лицензии.
2. Учесть пробелы, кириллицу, немецкие имена, двойное `.png.png` и кириллическую `с` в начале двух `сhristmas-...`. ID нельзя получать наивным удалением расширения или ручным исправлением похожих букв. При генерации производных проверять коллизии.
3. Подготовить лёгкие прозрачные превью для библиотек/миниатюр и подходящий экранный размер. Крупные изображения для печати загружать по потребности; не включать все 130 МиБ в начальную загрузку и не записывать PNG/base64 в `localStorage`.
4. Оригинал/печатную версию не растягивать и не снижать до размера экранной миниатюры. Сохранять alpha; проверить края на светлом, кремовом и цветном фоне. Указать ограничение качества при чрезмерном физическом увеличении.
5. В PDF повторно использовать уже встроенное изображение по `assetId`, где это поддерживает адаптер; проверять память на наборе из 31 карточки.
6. Разметить реальные категории из требований. Не показывать пустые категории как готовый контент; обнаруженные пробелы покрытия занести в контентные задачи. Приоритет — существующие PNG, новые изображения без необходимости не заказывать.
7. Сделать несколько законченных шаблонов на общей системе данных. Рабочий стартовый набор: «Хвойная сказка» (`christmas-tree-with-wooden-ornaments.png`), «Зимние истории» (`fairytale-winter-teremok-in-the-snow.png`), «Винтажный праздник» (`vintage-arrangement-of-christmas-tree-ornaments.png`). ## 6. Агентская команда и владение файлами

Одновременно работают координатор и до трёх исполнителей. Роли постоянны, задачи выдаются волнами; не требуется отдельный агент на каждый компонент.

| Роль | Основное владение | Ответственность |
| --- | --- | --- |
| A — координатор / интегратор | `src/app`, общие конфиги, зависимости/lockfile, `scripts`, `src/content`, CI, документация, сквозные fixtures | Контракты и согласованность требований, scaffold, каталог, интеграция, review, финальная приёмка. |
| B — UI / дизайн | `src/shared/ui`, `src/styles`, все `src/features` | Сходство с образцом, оболочка, галерея, инспектор, адаптивность, справка/тур; только команды через application API. |
| C — модель / состояние | `src/domain/project`, `src/domain/commands`, `src/application/project-store`, `history`, `persistence`, `src/infrastructure/storage` | Инварианты, создание, команды, массовые операции, история, autosave/recovery. |
| D — графика / печать | `src/domain/geometry`, `validation`, `src/rendering`, `src/application/export`, `src/infrastructure/assets`, `pdf` | Геометрия, текст/шрифты, SVG, interaction controller, валидация, раскладка и PDF. |

Тесты конкретного модуля принадлежат его владельцу, общие сценарии и fixtures — A. Изменения публичных типов, зависимостей и чужих каталогов согласуются сообщением с владельцем; это рабочая координация агентов, отдельного разрешения пользователя на каждую правку не требуется.

До старта параллельной работы A создаёт общие интерфейсы и минимальные fixtures. Если агенту нужен ещё не готовый модуль, он работает через согласованный контракт и fixture, затем заменяет адаптер реальным. Нельзя оставлять имитацию скачивания PDF, несохраняемый редактор или статичные миниатюры как готовую функцию.

### T06. Геометрия, SVG и управление на карточке — D; интеграция UI B

Зависимости: T01, T03, T05.

При смене формы координаты сохраняются, если допустимы; несовместимость разбирается до фиксации изменения, без молчаливого выхода отверстия наружу.

Готово: мышь, клавиатура и touch работают без конфликтов между вводом, перемещением элемента и pan; одна завершённая трансформация отменяется одним Undo. Масштаб экрана не меняет печатные размеры.

### T07. Правая панель и массовые операции — B, команды C

Зависимости: T03–T06; часть панелей можно делать раньше по контрактам.

- **Текст:** содержимое, поддерживаемые шрифт/начертание, 6–72 pt, цвет, left/center/right, координаты и размер блока; без underline/strike/rotation/opacity.
- **Изображение:** каталог, замена без подтверждения, положение, габаритная рамка и угол. При замене сохранять рамку/угол и вписывать новый PNG с сохранением пропорций.
- **Фон:** solid, linear/radial gradient до трёх цветов; направление/центр, пресеты, форма/размеры карточки и hole. Изменение геометрии сопровождается предупреждением о последствиях, пропорциональным преобразованием по принятой политике и повторной проверкой.
- **Два уровня отверстия:** общий toggle в настройках проекта добавляет отверстия всем карточкам или удаляет их со всех; значение учитывается фабрикой проекта. Во вкладке «Фон» добавление/удаление отверстия действует только на текущую карточку и не меняет остальные. Это разные команды с явно обозначенной областью действия.
- **Декорации:** круг/звезда, максимум 10; ширина/высота до 20 мм, fill/stroke или их отсутствие, обводка 0,25–3 pt, звезда 4–8 лучей. Без поворота и прозрачности.
- Общие недавние цвета: шесть уникальных значений для всех цветовых контролов, сохраняются отдельно от истории проекта.
- Scope «Текущая карточка / Весь набор» возвращается к текущей после операции. Массовая замена оформления не перезаписывает текст и индивидуальные позиции текстовых блоков.
- «Добавить на все» пропускает карточки с 10 декорациями и сообщает номера. Настройки существующих кругов/звёзд не меняют их индивидуальные размеры/позиции. Массовое удаление типа требует подтверждения с типом и количеством; единичное удаление отменяется историей без отдельного подтверждения.
- Миниатюры всегда отражают актуальный дизайн, имеют постоянные номера, contain, независимые индикаторы error/warning, прокрутку/стрелки и центрирование активной карточки. Активная вкладка и scroll панели сохраняются при переключении карточек.

Готово: все разрешённые свойства редактируются, массовые операции соблюдают исключения и атомарность; оформление выбранной миниатюры не скрывает индикаторы проблем.

### T08. Автосохранение и восстановление — C; окна B

Зависимость: T03; базовая версия нужна для T05, полный recovery — к финальной приёмке.

Готово: reload восстанавливает реальное последнее сохранённое состояние; испорченный JSON, неизвестная schema и ошибка записи не приводят к тихой потере исходника.

## 9. Проверки и критерии приёмки v1

Проверки пишутся для поведения и рисков: точность печати, инварианты, история, массовые изменения, восстановление. Не покрывать тестами каждую CSS-величину и тривиальную обёртку компонента. Визуальное сходство подтверждается скриншотами и просмотром, touch/keyboard — целевыми сценариями.

## 10. Формат задания и передачи работы между агентами

Каждая выдача задачи содержит ID из §7, цель, входные контракты, разрешённые каталоги, зависимости и критерии «Готово». Агент сначала читает §1–§5 и профильные исходные требования. Новые расхождения сообщает координатору с конкретными ссылками; функциональный объём самостоятельно не расширяет.

При передаче агент сообщает:

- Что реализовано и какой пользовательский сценарий теперь работает.
- Какие публичные контракты/файлы изменены и что требуется подключить другим владельцам.
- Какие проверки выполнены, результат и воспроизводимые шаги для ручной проверки.
- Какие ограничения остались и какая следующая задача их закрывает.

Координатор интегрирует после каждой волны и проверяет общий сценарий на реальных данных. Нельзя считать задачу завершённой только по компиляции изолированного компонента или скриншоту статичного макета.
